# Fleet mode threat model (STRIDE)

Scope: fleet mode as shipped in v0.10.2 plus the three fixes listed under "Found by fuzzing". An agent
(`pqcscan agent`, `pqcscan scan --report-to`) enrolls with a collector (`pqcscan daemon`), posts gzip JSON scan
bundles, and operators read the result through `/fleet`, `/api/fleet`, `pqcscan fleet`, `pqcscan agents` and the fleet
exports. [FLEET.md](../FLEET.md) (Security, Known limits) is the operator-facing statement of the same limits.

Evidence: unit and integration tests under `tests/`, and hypothesis fuzz targets under `tests/fuzz/`. Run the fuzz
targets with `pip install -e '.[verify]'` then `pytest -m fuzz tests/fuzz`; `PQCSCAN_FUZZ_EXAMPLES=5000` raises the
example count from the default 200. Every test id below is `path::function` relative to the repository root, and
`tests/unit/test_fleet_threat_model_gaps.py` holds the abuse cases that no earlier test pinned down.

## Assets

| Asset | Why it matters | Where it lives |
|---|---|---|
| A1 Site token | Full operator access: read every host's findings, revoke hosts, export. | `--token` / `PQCSCAN_TOKEN`, collector memory; browser session ids in collector memory |
| A2 Enroll token | Lets its holder mint agent tokens for any machine id. | `--enroll-token` / `PQCSCAN_ENROLL_TOKEN`; agent env or command line on first run |
| A3 Agent token | Identity of one host at the collector: can post bundles as that host. | Agent `agent.token` (0600); collector stores only its SHA-256 |
| A4 Findings database | A map of every host's quantum-vulnerable cryptography: paths, endpoints, algorithms. Reconnaissance value. | Collector DB (SQLite file or Postgres); agent `agent.db`; spool bundles |
| A5 Verdict integrity | Readiness bands, drift, Mosca inputs and fleet exports drive migration decisions. | Derived at ingest and at report time |
| A6 Collector availability | Ingest outage means spooling, then stale hosts. | Daemon process, DB |
| A7 Host identity record | Machine id, hostname, labels. Labels set Mosca inputs. | `hosts` table |

## Trust boundaries

```
 agent host                    proxy (optional)                collector                      operator
 +--------------------+  TB1   +----------------+  TB3   +---------------------------+  TB2  +-----------+
 | agent process      |------->| TLS, body cap, |------->| daemon/app.py guards      |<------| browser,  |
 | state dir (0700)   |  HTTPS | Host rewrite   |        | daemon/fleet.py handlers  |  site | CLI       |
 | token, spool, DB   |        +----------------+        | store/repo.py -> DB (TB5) |  token+-----------+
 +--------------------+                                   +---------------------------+
        ^ TB4: other local users and processes on the agent host
```

| Boundary | Crossed by | Authentication and limits |
|---|---|---|
| TB1 agent to collector | enroll body (64 KiB), ingest bundle (8 MiB wire, 50 MiB raw, 200,000 findings) | enroll token on enroll; agent bearer token on ingest; https required off loopback (`cli/_report.py:check_server_scheme`) |
| TB2 operator to collector | site token as bearer or session cookie; `/fleet`, `/api/fleet*`, exports, revoke | `daemon/app.py:_guard`: Host allowlist, Origin must match Host on writes, site token |
| TB3 proxy to collector | forwarded requests | the proxy must not add basic auth on `/api/ingest` and `/api/agents/enroll`; `--allow-host` names the public Host |
| TB4 local users on the agent host | state dir, token file, spool, agent DB | file modes only (0700 dir, 0600 files); no OS-level isolation beyond that |
| TB5 collector to database | SQLAlchemy ORM statements | bound parameters; DB file permissions are the operator's |

Out of scope: the scanner probes themselves, the packaging recipes' behaviour on real Windows and IBM i hosts, and
anything a root user on the agent host or the collector host can do.

## Accepted risks (cited from FLEET.md)

| Ref | Accepted risk | Source | Rows |
|---|---|---|---|
| AR1 | Anyone holding the enroll token can enroll any machine id, including an existing one (which rotates that host's token). | FLEET.md Security, "Enroll token" | E1, E2 |
| AR2 | Guessing the enroll token is not rate limited. | FLEET.md Security, "No throttling on enrollment" | E1, E7 |
| AR3 | A revoked host cannot re-enroll until an operator unrevokes it; its bundles spool locally and replay after that. | FLEET.md Security "Revoked hosts stay out"; Known limits "Permanent rejections" | E4, S4 |
| AR4 | `windows-task.ps1` has run only under Pester on GitHub's `windows-2022` and `windows-latest` runners. Windows Server 2019, Windows 11 and real hosts are untested, a non-SYSTEM `-RunAs` account cannot finish the install, and the other recipes are checked by text assertions only (`tests/unit/test_fleet_recipes.py`). | FLEET.md Deployment recipes; spec "Environment constraints" | D3, T3 |
| AR5 | Nothing prunes `spool/rejected/`. | FLEET.md Known limits | S6 |
| AR6 | Postgres runs the fleet tests in CI (120 pass) but is not profiled, and under the load test it was no faster than SQLite. | FLEET.md Known limits | I13, X5 |
| AR7 | A host with a valid token is trusted about itself: nothing attests that its findings are true. | design | I5 |

Each accepted risk keeps a row below so it has an owner.

## Found by fuzzing

Three product bugs came out of building the hypothesis targets. Each has its own commit, regression test and CHANGELOG line, and each fails the matching fuzz target on v0.10.2.

| Bug | Row | Fix |
|---|---|---|
| A gzip body cut off inside its CRC and length trailer inflated to complete JSON and was stored. | I4 | `load_bundle` requires the end of the gzip stream. |
| A 512-character title of one-letter host tokens normalised to about 1,800 characters, so a parity key outgrew the cap that FLEET.md and the code comment promise. | I13 | The normalised title is cut at 512 characters. |
| The 64-label cap was checked per bundle, but labels merge across bundles, so a host could grow its label set without bound. FLEET.md already said "64 per host". | E9 | `_apply_identity` drops new keys past 64 and logs a warning; the scan is never refused over labels. |
